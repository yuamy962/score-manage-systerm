## 1. 背景与目标

在现有部门积分绩效管理系统（Next.js 14 + NestJS 10 + Prisma + PostgreSQL）基础上，新增「知识中心」模块，实现部门知识的沉淀闭环：

```
员工录入 → AI 整理 → 本人确认 → 提交审核 → 负责人审核发布 → AI 助手检索问答 → 未答问题沉淀为知识缺口 → 转为新知识（回流）
```

核心原则：**员工只负责把知道的说出来，格式化工作交给 AI**；AI 只基于已审核发布的正式知识作答，不编造。

## 2. 总体设计

### 2.1 数据模型（两级结构：系统 → 模块）

| 模型 | 说明 |
|---|---|
| `SystemModule` | 「系统」层，复用系统既有配置表，避免重复建设 |
| `KnowledgeModule` | 「模块」层，新建表，归属某个系统，MANAGER 维护 |
| `Knowledge` | 知识主体：标题、类型（BASIC/PROCESS/TROUBLE）、状态（DRAFT→PENDING→PUBLISHED→OFFLINE）、权限（NORMAL/RESTRICTED）、使用次数 |
| `KnowledgeVersion` | 版本快照：概述/详情/补充/注意事项 + contentText + 关键词，审核即生成版本 |
| `KnowledgeAttachment` | 附件（本期为占位，上传功能待实现） |
| `KnowledgeQuestionLog` | AI 问答日志：问题、回答、命中知识 ID 列表、是否命中、来源（performance_system/wecom） |
| `KnowledgeGap` | 知识缺口：问题、提问人、处理人、状态（PENDING/PROCESSING/RESOLVED/CONVERTED）、处理说明、关联知识 |

### 2.2 AI 集成（DeepSeek）

- **AI 整理（organize）**：员工填口语化原始内容 → AI 按知识类型模板生成结构化内容 + 标题 + 关键词。
- **AI 问答（ask）**：RAG 流程，检索 → 拼接上下文 → 模型作答。
- **检索打分算法**（无分词/向量库环境下的轻量方案）：
  - 关键词命中：每个 +5 分
  - 标题二元组（bigram）命中率 × 4
  - 正文二元组命中率 × 3
  - 阈值 2.5，取 Top 3 作为上下文
- **ASK_PROMPT 约束**：只依据给定知识回答；禁止编造、禁止生成生产 SQL/命令/IP/账号/Token；知识不足时返回统一话术；回答末尾列出来源。

### 2.3 权限设计（复用现有 RBAC，未新增角色）

| 功能 | MEMBER | PM | MANAGER |
|---|---|---|---|
| 录入/提交知识 | ✓ | ✓ | ✓ |
| 审核发布 | - | ✓ | ✓ |
| 模块维护（`modules/all`） | - | - | ✓ |
| 检索受限知识（RESTRICTED） | - | ✓ | ✓ |
| 缺口处理/转知识 | 仅查看本人提交 | ✓ | ✓ |

## 3. 开发过程（分阶段）

### 阶段一 P0：知识录入与审核（已完成）

1. **Schema 设计与迁移**：新增知识相关 6 张表，补齐双向关系（`@relation("Versions")`）。
2. **后端 knowledge 模块**：模块 CRUD、知识 CRUD、`organize`（AI 整理）、`submit`、`review`、`my/pending/published/detail`。
3. **前端**：
   - 三个知识菜单合并为单菜单「知识中心」+ 顶部 Tab（旧路由 `/knowledge/my`、`/knowledge/review` 重定向兼容）；
   - 模块级联按需加载（非 MANAGER 走 `modules?systemModuleId=`）。
4. **新增知识重构为 4 步向导**（响应产品体验要求）：
   - ① 选择知识类型（三张大卡片）→ ② 填写原始内容（单栏居中、模板字段随类型切换、口语化提示语）→ ③ AI 整理（左右对比：原始 vs 整理结果，支持重新整理/手工修改/确认）→ ④ 确认提交（预览 + 提交成功页）。
   - 步骤条：完成的 ✓、当前蓝色高亮、未完成灰色。

### 阶段二 P1：AI 知识助手与知识缺口（本轮完成）

1. **Schema**：新增 `KnowledgeQuestionLog`、`KnowledgeGap`、`KnowledgeGapStatus` 枚举，迁移完成。
2. **后端**：
   - `POST /knowledge/ask`：检索打分 → AI 作答 → 返回 `{answer, matched, sources[]}`；未命中返回统一话术并记日志（`matched:false`）；命中知识 `usageCount+1`；权限过滤（受限知识仅 PM/MANAGER 可检索）。
   - `POST/GET /knowledge/gaps`、`PATCH /knowledge/gaps/:id`、`POST /knowledge/gaps/:id/convert`：缺口记录/列表（角色过滤）/处理/转知识。
3. **前端**：
   - `AskPanel`：聊天气泡式问答面板，气泡下方展示知识来源（标题+版本）；AI 检索中动画；未命中时出现「+ 记录为知识缺口」按钮，一键沉淀；
   - `GapPanel`：状态 Tab 筛选（全部/待处理/处理中/已解决/已转知识），PM/MANAGER 可「开始处理 / 标记解决（附处理说明）/ 转为知识」；
   - **缺口转知识闭环**：GapPanel 点「转为知识」→ 切到「我的知识」Tab 自动打开向导并预填问题为标题 → 创建知识成功后自动调 convert 关联缺口、状态置 CONVERTED；
   - `api.ts` 扩展 `ask` / `createGap` / `gaps` / `updateGap` / `convertGap`。
4. **知识中心 Tab 定稿**：知识库 / AI 知识助手 / 我的知识 / 知识审核（仅 PM/MANAGER 可见）/ 知识缺口。

## 4. 关键决策记录

1. **复用 `SystemModule` 作为系统层**，只新建模块层表，避免系统数据重复维护。
2. **审核人映射到现有 PM/MANAGER 角色**，不新增「知识审核员」角色，降低权限体系复杂度。
3. **检索采用轻量打分而非向量库**：当前规模（部门级、百条内）下 bigram+关键词加权足够，后续数据量增大可平滑替换为 pgvector。
4. **版本快照设计**：审核通过才生成不可变版本，AI 问答只取 `currentVersion`，保证引用来源稳定。
5. **缺口转知识走向导闭环**而非直接弹窗填写，保证新知识同样经过 AI 整理与审核流程。

## 5. 问题与解决记录

| # | 问题 | 解决方式 |
|---|---|---|
| 1 | Prisma 报关系缺反向字段 | 为 `Knowledge↔KnowledgeVersion` 补 `@relation("Versions")` |
| 2 | PostgreSQL 认证失败（P1000） | 重装 PG，新建 `scoreuser`/`scoremanage`，`.env` 重新对齐 |
| 3 | 迁移报无法创建 shadow database（P3014） | `ALTER USER scoreuser CREATEDB;` |
| 4 | seed 报 `ON CONFLICT` 无唯一约束 | 手动建唯一索引并补正式迁移固化 |
| 5 | Prisma generate 报 EPERM | 停后端 → 删旧 query engine DLL → 重新 generate |
| 6 | DeepSeek 返回异常模型/内容 | 检查 API Key 权限与 `DEEPSEEK_MODEL` 配置 |
| 7 | `restart.bat` 报 `'cho' 不是内部或外部命令` | 脚本转 GBK 编码 + `chcp 936`，并在启动前清理 `.next` 防 build/dev 冲突 |
| 8 | PowerShell 直连测试中文变乱码，产生乱码知识并干扰检索验证 | 请求体改 UTF-8 字节发送（`[Text.Encoding]::UTF8.GetBytes`）；清理乱码测试数据 |
| 9 | TS1016 必选参数位于可选参数后 | 调整 `listGaps` 控制器参数顺序 |

> 教训：Windows PowerShell 5.1 直连测中文接口时，`Invoke-RestMethod -Body` 默认按本地编码序列化，中文会变成 `?`，既污染数据也导致误判。**测试中文 API 务必显式 UTF-8 字节编码**；前端页面无此问题。
