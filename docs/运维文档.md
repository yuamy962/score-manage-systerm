### 1.2 表字段详细说明

#### users（用户表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | String | PK, cuid | 用户唯一标识 |
| name | String | NOT NULL | 真实姓名 |
| role | Enum | NOT NULL, 默认 MEMBER | 角色：MEMBER/PM/MANAGER |
| status | Boolean | 默认 true | 账号启用状态，false 为已禁用（软删除） |
| username | String | UNIQUE | 登录用户名 |
| password | String | | bcrypt 哈希密码 |
| openid | String | UNIQUE | 微信 openid（小程序预留） |
| unionid | String | | 微信 unionid（小程序预留） |
| phone | String | | 绑定手机号 |
| createdAt | DateTime | 默认 now() | 创建时间 |
| updatedAt | DateTime | 自动更新 | 更新时间 |

#### tasks（任务表）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | String | PK, cuid | 任务唯一标识 |
| title | String | NOT NULL | 任务标题 |
| description | String | | 任务描述（V1.3 新增） |
| estimatedDays | Float | NOT NULL | 预估工作量（人日） |
| finalDays | Float | | 最终工作量（人日），默认等于预估工作量 |
| taskType | Enum | 默认 REQUIREMENT_DEV | 任务类型：REQUIREMENT_DEV/OPS_SUPPORT |
| taskSource | Enum | 默认 OTHER | 任务来源：PROJECT/REQUIREMENT/OTHER |
| taskAction | Enum | 默认 SELF_DEV | 任务动作：SELF_DEV/NON_SELF_DEV |
| scoreRatio | Float | 默认 1.00 | 积分转换比例（自研=1.00，非自研=0.60） |
| planFinishAt | DateTime | | 计划完成时间 |
| actualStartAt | DateTime | | 实际开始时间（系统自动记录） |
| actualFinishAt | DateTime | | 实际完成时间（系统自动记录，驳回后更新） |
| status | Enum | 默认 DRAFT | 任务状态（见状态枚举说明） |
| isPoolTask | Boolean | 默认 false | 是否为任务池任务 |
| claimedBy | String | FK → users.id | 领取人 ID（CLAIMED 状态时使用） |
| claimRatio | Float | | 领取时的贡献比例 |
| weightDev | Float | 默认 0.40 | 开发实现权重 |
| weightTest | Float | 默认 0.25 | 测试验证权重 |
| weightDebug | Float | 默认 0.20 | 客户联调权重 |
| weightOnline | Float | 默认 0.10 | 上线支撑权重 |
| weightDoc | Float | 默认 0.05 | 文档培训权重 |
| createdBy | String | FK → users.id, NOT NULL | 创建人 |
| createdAt | DateTime | 默认 now() | 创建时间 |
| updatedAt | DateTime | 自动更新 | 更新时间 |

**任务状态枚举（TaskStatus）**：

| 枚举值 | 中文名 | 说明 |
|--------|--------|------|
| POOL | 任务池中 | 任务池任务，等待领取 |
| CLAIMED | 待确认 | 已领取，等待项目经理确认 |
| DRAFT | 草稿 | 项目经理创建中 |
| PENDING | 待执行 | 已分配负责人，等待开始 |
| IN_PROGRESS | 执行中 | 成员正在处理 |
| IN_REVIEW | 待审核 | 成员已提交完成，等待审核 |
| REJECTED | 已驳回 | 审核不通过，退回执行中 |
| COMPLETED | 已完成 | 审核通过，积分已入账 |
| CANCELLED | 已取消 | 任务已取消 |

#### task_assignments（任务分配表）

## 二、业务流程

### 2.1 标准任务流程

```
项目经理创建任务
       │
       ▼
   ┌─────────┐
   │  草稿    │ ← 项目经理编辑中
   └────┬────┘
        │ 提交任务
        ▼
   ┌─────────┐
   │  待执行  │ ← 已分配负责人
   └────┬────┘
        │ 成员点击"开始"
        │ 系统自动记录 actualStartAt
        ▼
   ┌─────────┐
   │  执行中  │ ← 成员处理中
   └────┬────┘
        │ 成员点击"提交完成"
        │ 系统自动记录 actualFinishAt
        │ ★ 触发企微群通知
        ▼
   ┌─────────┐
   │  待审核  │ ← 等待项目经理审核
   └────┬────┘
        │
   ┌────┴────┐
   │         │
   ▼         ▼
审核通过   审核驳回
   │         │
   ▼         ▼
┌────────┐ ┌────────┐
│ 已完成  │ │ 已驳回  │ → 返回执行中
└────────┘ └────────┘
   │
   ▼
系统自动计算积分
按贡献比例分配到各负责人
effectMonth = 审核通过时间所在月份
```

### 2.2 任务池流程

```
项目经理创建任务池任务
       │
       ▼
   ┌─────────┐
   │  任务池  │ ← 等待成员领取
   └────┬────┘
        │ 成员领取
        ▼
   ┌─────────┐
   │  待确认  │ ← 等待项目经理确认领取
   └────┬────┘
        │
   ┌────┼────────────┐
   │    │             │
   ▼    ▼             ▼
 确认  驳回领取     取消领取
   │    │             │
   ▼    ▼             ▼
待执行  返回任务池   返回任务池
   │
   ▼
（进入标准任务流程）
```

### 2.3 积分计算流程

```
任务审核通过
       │
       ▼
获取任务最终工作量 finalDays（默认=estimatedDays）
       │
       ▼
遍历所有 task_assignments
       │
       ▼
对每个负责人计算：
  个人积分 = finalDays × ratio × scoreRatio
       │
       ▼
确定积分类型：
  taskType=OPS_SUPPORT → ScoreType.OPS
  其他 → ScoreType.REQUIREMENT
       │
       ▼
创建 score_record：
  - effectMonth = 审核通过时间的 YYYY-MM
  - reason = 自动生成（含任务标题、比例、工作量）
  - approvedBy = 审核人
       │
       ▼
积分入账，参与月度排行
```

### 2.4 申诉流程

```
成员发起申诉（3个工作日内）
       │
       ▼
   ┌─────────┐
   │  待处理  │
   └────┬────┘
        │ 项目经理复核
        ▼
   ┌─────────┐
   │  复核中  │
   └────┬────┘
        │ 部门经理裁定
        ▼
   ┌─────────┐
   │  已裁定  │ → 结果不可再次申诉
   └─────────┘
```

### 2.5 企微群通知流程（V1.3 新增）

#### 任务提交审核通知

```
成员提交任务完成（IN_PROGRESS → IN_REVIEW）
       │
       ▼
TasksService.updateStatus() 检测状态变更
       │
       ▼
NotificationService.notifyTaskSubmitted(task)
       │
       ▼
构造飞书卡片消息：
  - 任务标题
  - 提交人
  - 预估工作量 / 提交工作量
  - 提交时间
  - 查看任务按钮
       │
       ▼
生成签名（timestamp + secret）
       │
       ▼
HTTP POST → 飞书群机器人 Webhook（携带签名头）
       │
       ▼
飞书群收到卡片通知消息
```

#### 到期任务每日提醒

```
每天 10:00（Asia/Shanghai）
       │
       ▼
@Cron 定时任务触发
NotificationService.notifyExpiringTasks()
       │
       ▼
查询数据库：
  - status IN (PENDING, IN_PROGRESS, IN_REVIEW)
  - planFinishAt ≤ 2天后
       │
       ▼
按紧急程度分组：
  🔴 已逾期（planFinishAt < 今天）
  🟠 明天到期
  🟡 2天内到期
       │
       ▼
构造飞书卡片汇总消息
       │
       ▼
生成签名（timestamp + secret）
       │
       ▼
HTTP POST → 飞书群机器人 Webhook（携带签名头）
```

## 三、通知机制配置

### 3.1 飞书群机器人配置

| 配置项 | 环境变量 | 说明 |
|--------|---------|------|
| Webhook URL | `FEISHU_WEBHOOK_URL` | 在飞书群中添加机器人后获取 |
| 签名密钥 | `FEISHU_SECRET` | 开启签名校验后生成的密钥 |

**获取步骤**：
1. 打开飞书群聊 → 点击右上角「···」→「群机器人」
2. 点击「添加机器人」→「自定义机器人」
3. 填写机器人名称（如"任务通知助手"），上传头像
4. 在安全设置中勾选「签名校验」，复制生成的签名密钥
5. 复制 Webhook URL
6. 将 URL 和密钥填入后端 `.env` 文件

### 3.2 通知触发条件

| 通知类型 | 触发条件 | 推送格式 | 频率 |
|---------|---------|---------|------|
| 任务下发通知 | 任务分配负责人后 | 飞书卡片 | 实时 |
| 任务提交审核 | 任务状态从 IN_PROGRESS → IN_REVIEW | 飞书卡片 | 实时 |
| 到期任务提醒 | 每天早上 10:00 | 飞书卡片 | 每日一次 |
| 本周之星 | 每周五下午 17:30 | 飞书卡片 | 每周一次 |
| 月末冲刺提醒 | 每月最后3天早上 9:00 | 飞书卡片 | 每月一次 |
| 里程碑达成 | 用户累计积分达到里程碑 | 飞书卡片 | 实时 |
| 徽章获得 | 用户获得成就徽章 | 飞书卡片 | 实时 |

### 3.3 到期提醒范围

| 分组 | 条件 | 标记 |
|------|------|------|
| 已逾期 | planFinishAt < 当天 0:00 | 🔴 |
| 明天到期 | 当天 0:00 ≤ planFinishAt ≤ 明天 23:59 | 🟠 |
| 2天内到期 | 明天 23:59 < planFinishAt ≤ 2天后 23:59 | 🟡 |

> 仅提醒状态为 PENDING、IN_PROGRESS、IN_REVIEW 的未完成任务。

## 四、运维操作指南

### 4.1 启停脚本

#### Windows 环境

| 脚本 | 命令 | 说明 |
|------|------|------|
| 启动 | 双击 `start.bat` | 分别启动后端和前端（独立窗口） |
| 停止 | 双击 `stop.bat` | 终止所有前后端进程 |
| 重启 | 双击 `restart.bat` | 先停止再启动 |

#### Linux 环境

```bash
# 首次使用需赋予执行权限
chmod +x start.sh stop.sh restart.sh

# 启动
./start.sh

# 停止
./stop.sh

# 重启
./restart.sh
```

Linux 脚本说明：
- 后台运行，日志输出到项目根目录的 `backend.log` 和 `frontend.log`
- 进程 PID 记录在 `.backend.pid` 和 `.frontend.pid` 文件中
- 停止时优先按 PID 终止，PID 文件不存在时按端口查找进程

### 4.2 生产环境部署

#### PM2 进程管理

```bash
# 启动后端
cd /opt/score-manage/backend
pm2 start dist/main.js --name score-backend

# 查看状态
pm2 list

# 查看日志
pm2 logs score-backend

# 重启
pm2 restart score-backend

# 停止
pm2 stop score-backend
```

#### 前端部署

```bash
cd /opt/score-manage/frontend
npm run build
# 由 Nginx 托管静态资源
```

### 4.3 数据库运维

```bash
# 数据库迁移（生产环境）
cd backend
npx prisma migrate deploy

# 查看数据库（可视化）
npx prisma studio

# 重新生成 Prisma Client
npx prisma generate

# 重置数据库（⚠️ 会删除所有数据）
npx prisma migrate reset
```

### 4.4 常见问题排查

| 问题 | 排查方式 |
|------|---------|
| 后端无法启动 | 检查 `.env` 中 DATABASE_URL 是否正确；检查 PostgreSQL 是否运行 |
| 前端无法连接后端 | 检查后端是否在 3001 端口运行；检查 next.config.js 中的代理配置 |
| 企微通知未发送 | 检查 WECOM_WEBHOOK_URL 是否配置；查看后端日志中 NotificationService 的输出 |
| 定时提醒未触发 | 确认后端服务持续运行；检查系统时区是否为 Asia/Shanghai |
| 数据库连接失败 | 检查 PostgreSQL 服务状态；检查 pg_hba.conf 是否允许本地连接 |

### 4.5 环境变量清单

| 变量名 | 必填 | 默认值 | 说明 |
|--------|------|--------|------|
| DATABASE_URL | 是 | - | PostgreSQL 连接字符串 |
| JWT_SECRET | 是 | - | JWT 签名密钥，生产环境必须更换 |
| JWT_EXPIRES_IN | 否 | 7d | Token 过期时间 |
| PORT | 否 | 3001 | 后端服务端口 |
| NODE_ENV | 否 | development | 运行环境 |
| WECOM_WEBHOOK_URL | 否 | 空 | 企微群机器人 Webhook URL，为空则不发送通知 |

| 认证 | JWT (passport-jwt) | 用户认证 |
| 权限 | RBAC（自定义守卫） | 角色权限控制 |
| 定时任务 | @nestjs/schedule | 企微定时提醒 |

| 进程管理 | PM2 | 生产环境进程守护 |
