## 三、数据库模型关系

```
users (用户)
  ├── 1:N tasks (创建的任务)
  ├── 1:N task_assignments (被分配的任务)
  ├── 1:N score_records (积分记录)
  ├── 1:N appeals (发起的申诉)
  └── 1:N operation_logs (操作日志)

tasks (任务)
  ├── N:1 users (创建者)
  ├── 1:N task_assignments (分配记录)
  └── 1:N score_records (关联积分)

task_assignments (任务分配)
  ├── N:1 tasks
  └── N:1 users

score_records (积分记录)
  ├── N:1 users (积分获得者)
  ├── N:1 tasks (关联任务，可为空)
  └── 1:N score_adjustments (调整记录)
  └── 1:N appeals (关联申诉)

score_adjustments (积分调整)
  └── N:1 score_records

appeals (申诉)
  ├── N:1 score_records
  ├── N:1 users (申诉人)
  └── N:1 users (裁定人)
```

## 四、本地开发环境搭建

### 前置依赖

- Node.js ≥ 18
- PostgreSQL ≥ 14（本地或远程）
- npm 或 yarn

### 步骤 1：安装依赖

```bash
# 进入项目根目录
cd score-manage-systerm

# 安装后端依赖
cd backend
npm install

# 安装前端依赖
cd ../frontend
npm install
```

### 步骤 2：配置环境变量

```bash
cd backend
cp .env.example .env
```

编辑 `.env` 文件：

```env
# 数据库连接（本地开发示例）
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/scoremanage?schema=public"

# JWT密钥（生产环境必须更换为强密码）
JWT_SECRET="your-super-secret-jwt-key-change-this-in-production"

# Token过期时间
JWT_EXPIRES_IN="7d"

# 服务端口号
PORT=3001

# 环境
NODE_ENV="development"

# 企微群机器人Webhook URL（在企微群中添加机器人后获取）
WECOM_WEBHOOK_URL=""
```

### 步骤 3：初始化数据库

```bash
cd backend

# 生成Prisma Client
npx prisma generate

# 执行数据库迁移（创建表结构）
npx prisma migrate dev --name init

# 导入初始化数据（3个测试账号）
npx prisma db seed
```

### 步骤 4：启动服务

**终端1 — 启动后端：**
```bash
cd backend
npm run start:dev
```

**终端2 — 启动前端：**
```bash
cd frontend
npm run dev
```

### 访问地址

| 服务 | 地址 |
|------|------|
| 前端页面 | http://localhost:3000 |
| 后端API | http://localhost:3001 |
| API文档（Swagger） | http://localhost:3001/api/docs |

## 六、核心业务流程验证

### 流程1：需求任务积分发放

1. **项目经理** 登录 → 任务管理 → 新建任务
2. 填写任务标题、工作量、计划完成时间、分配成员
3. **普通成员** 登录 → 任务管理 → 点击"开始"（状态：待执行→执行中）
4. 成员处理完成后 → 点击"提交完成"（状态：执行中→待审核，系统自动记录实际完成时间）
5. **项目经理** → 任务管理 → 点击"审核通过"
6. 系统自动按贡献比例计算并发放积分

### 流程2：运维积分申请

1. **普通成员** → 积分管理 → 提交运维积分申请（选择等级、填写说明）
2. **项目经理** → 积分管理 → 审核通过
3. P1级重大故障需 **部门经理** 终审

### 流程3：申诉流程

1. **普通成员** → 申诉管理 → 选择积分记录 → 填写理由 → 提交申诉
2. **项目经理** → 申诉管理 → 点击"初审通过"
3. **部门经理** → 申诉管理 → 点击"支持"或"驳回"

## 七、生产部署（腾讯云轻量服务器）

### 7.1 服务器环境准备

```bash
# 更新系统
sudo apt update && sudo apt upgrade -y

# 安装 Node.js
 curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
 sudo apt install -y nodejs

# 安装 PostgreSQL
sudo apt install -y postgresql postgresql-contrib

# 安装 PM2
sudo npm install -g pm2

# 安装 Nginx
sudo apt install -y nginx
```

### 7.2 配置 PostgreSQL

```bash
# 切换到 postgres 用户
sudo -u postgres psql

# 在 psql 中执行
CREATE DATABASE scoremanage;
CREATE USER scoreuser WITH ENCRYPTED PASSWORD '你的强密码';
GRANT ALL PRIVILEGES ON DATABASE scoremanage TO scoreuser;
\q

# 修改监听配置
sudo nano /etc/postgresql/14/main/postgresql.conf
# 确保：listen_addresses = 'localhost'

# 重启 PostgreSQL
sudo systemctl restart postgresql
```

### 7.3 部署后端

```bash
# 上传项目到服务器（假设上传到 /opt/score-manage）
cd /opt/score-manage/backend

# 安装依赖
npm install --production

# 配置环境变量
nano .env
# 填入生产环境 DATABASE_URL、JWT_SECRET 等

# 执行数据库迁移
npx prisma migrate deploy
npx prisma db seed

# 构建项目
npm run build

# PM2 启动
pm2 start dist/main.js --name score-backend
pm2 save
pm2 startup
```

### 7.4 部署前端

```bash
cd /opt/score-manage/frontend

# 安装依赖
npm install

# 构建生产包
npm run build

# 前端为静态文件，Nginx直接托管
```

### 7.5 配置 Nginx

```bash
sudo nano /etc/nginx/sites-available/score-manage
```

写入配置：

```nginx
server {
    listen 80;
    server_name your-domain.com;  # 或服务器IP

    # 前端静态资源
    location / {
        root /opt/score-manage/frontend/out;  # 或 .next/static
        try_files $uri $uri/ /index.html;
    }

    # 后端API代理
    location /api/ {
        proxy_pass http://localhost:3001/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_cache_bypass $http_upgrade;
    }
}
```

启用配置：

```bash
sudo ln -s /etc/nginx/sites-available/score-manage /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx
```

### 7.6 防火墙配置

```bash
# 开放 HTTP(80) 和 HTTPS(443)
sudo ufw allow 'Nginx Full'

# 关闭 PostgreSQL 外网访问（重要！）
# 确保 pg_hba.conf 只允许本地连接
```

## 九、小程序对接预留

### 已预留的数据库字段

用户表 `users` 已包含以下字段，供小程序登录使用：

| 字段 | 类型 | 说明 |
|------|------|------|
| `openid` | String? @unique | 微信用户唯一标识 |
| `unionid` | String? | 微信开放平台统一标识 |
| `phone` | String? | 绑定手机号 |

### 小程序登录流程（后续实现）

1. 小程序调用 `wx.login()` 获取 `code`
2. 后端调用微信 `code2Session` 接口换取 `openid`
3. 根据 `openid` 查询/创建用户
4. 返回 JWT Token 给小程序
5. 小程序后续请求携带 Token，复用现有 RBAC 权限体系

> 小程序端可复用同一套 NestJS API，仅需增加 `/auth/wx-login` 接口。
